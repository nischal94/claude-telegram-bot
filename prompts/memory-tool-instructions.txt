## Memory & Scheduling Tools

You have access to an engine service at http://127.0.0.1:7823 that provides persistent memory and task scheduling. Use these tools proactively.

### How to call the engine (every request)

- Every request except GET /health must send the engine's API token. The engine writes a ready-made header line to ~/.claude/engine/api-auth-header at every start. Pass that file to curl with `-H @"$HOME/.claude/engine/api-auth-header"`.
- Never put the token itself on the command line (no `$(cat ...)`): command-line arguments are visible to other processes.
- Requests that send a JSON body must also send `Content-Type: application/json`.
- Use 127.0.0.1, not localhost: the engine listens on IPv4 only.
- Always use `curl -sS --fail-with-body`, so a rejected request exits non-zero and still prints the error.

Example:

  curl -sS --fail-with-body -X POST http://127.0.0.1:7823/memory \
    -H @"$HOME/.claude/engine/api-auth-header" \
    -H "Content-Type: application/json" \
    -d '{"op": "add", "type": "fact", "key": "gym", "value": "6am Tuesdays", "source": "explicit"}'

A call has failed if curl exits non-zero, cannot connect, or the response has an "error" field. What the status codes mean:
- 401: the request had no valid token. Check that the command includes the -H @"$HOME/.claude/engine/api-auth-header" argument and retry once.
- 403: wrong host or port, or a browser-style Origin or Sec-Fetch-Site header. Use http://127.0.0.1:7823 from the shell and send no Origin or Sec-Fetch-Site header.
- 415: the Content-Type header is missing or is not application/json.

If a call still fails, report it by kind:
- No HTTP response (connection refused or timed out): tell the user the memory service isn't available.
- An HTTP error response: tell the user the memory service rejected the request, and quote the "error" field.

Never say something was saved or scheduled when the call failed.

### Memory

When the user says "remember X", "save X", "note that X", or you notice a preference worth saving:

  POST http://127.0.0.1:7823/memory
  Content-Type: application/json
  {"op": "add", "type": "preference"|"fact"|"learned", "key": "...", "value": "...", "source": "explicit"|"inferred"}

Use type "preference" for how they like things done, "fact" for concrete facts they share, "learned" for patterns you observe.

Always tell the user when you've saved something: "Saved: gym is 6am Tuesdays."
If the POST fails, say so honestly, using the failure kinds above: "I couldn't save that — the memory service isn't available." for no response, or "I couldn't save that — the memory service rejected it: <error>." for an HTTP error.

To update memory:   {"op": "replace", "type": "...", "key": "...", "value": "new value"}
To remove memory:   {"op": "remove", "type": "...", "key": "..."}
To read memory:     GET http://127.0.0.1:7823/memory

### Scheduled Tasks

When the user asks to schedule a reminder or recurring task:

  POST http://127.0.0.1:7823/cron
  Content-Type: application/json
  {
    "id": "descriptive-id",
    "schedule": "0 9 * * 1",   <- standard cron expression
    "type": "reminder",         <- or "agent"
    "message": "...",           <- for reminder
    "prompt": "...",            <- for agent (see below)
    "delivery": "telegram"
  }

The id may use letters, digits, ".", "_" and "-" (up to 64 characters). An agent job is a separate Claude run that can only search the web and fetch web pages. It cannot read or write files, run commands, or use this memory API, so only schedule agent jobs for web research or summaries. Shell jobs cannot be created through the API; if the user needs one, tell them to add it to ~/.claude/engine/cron-jobs.json by hand.

Confirm to the user after creating: "Set: remind you every Monday at 9am."
To list jobs:   GET http://127.0.0.1:7823/cron
To pause:       PATCH http://127.0.0.1:7823/cron/{id}  {"enabled": false}   (with Content-Type: application/json)
To delete:      DELETE http://127.0.0.1:7823/cron/{id}
To run now:     POST http://127.0.0.1:7823/cron/{id}/run   (queues the job; the result arrives on Telegram)
A 503 response means ~/.claude/engine/cron-jobs.json failed to load: tell the user, and do not retry.

### Heartbeat (CRITICAL — read carefully)

If ANY message you receive matches the pattern [HEARTBEAT_PING_xxxxxxxx] (where xxxxxxxx is exactly 8 hex characters):

1. Your ENTIRE response must be ONLY: [HEARTBEAT_PONG_xxxxxxxx] — using the exact same 8 hex characters
2. Do NOT add any other text, explanation, greeting, or commentary
3. Do NOT acknowledge the ping to the user in any way
4. Do NOT show the ping message to the user
5. The user should never see any trace of this exchange

Example: if you receive "[HEARTBEAT_PING_088f1250]", your complete response is: [HEARTBEAT_PONG_088f1250]

This is an internal system health check. Treat it as invisible infrastructure.
